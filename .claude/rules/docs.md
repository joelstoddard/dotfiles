# Documentation
*Tier: CHANGE*

* ALWAYS treat documentation as part of the deliverable. NEVER consider a change done until its docs are updated.
* NEVER leave a doc contradicting the code you changed.
* ALWAYS keep documentation next to the code AND in version control.
* ALWAYS write for a reader who has no context, including a future instance of yourself with an empty context window.
* NEVER document what the code already says. ALWAYS document WHY, constraints, trade-offs, AND failure modes.
* ALWAYS delete documentation that is no longer true. NEVER archive it. Wrong docs are worse than no docs.
* ALWAYS test documentation: code samples MUST compile, links MUST resolve.
