# Documentation
*Tier: CHANGE*

* You MUST treat documentation as part of the deliverable. You MUST NOT consider a change done until its docs are updated.
* You MUST NOT leave a doc contradicting the code you changed.
* You MUST keep documentation next to the code AND in version control.
* You MUST write for a reader who has no context, including a future instance of yourself with an empty context window.
* You MUST NOT document what the code already says. You MUST document WHY, constraints, trade-offs, AND failure modes.
* You MUST delete documentation that is no longer true. You MUST NOT archive it. Wrong docs are worse than no docs.
* You MUST test documentation: code samples MUST compile, links MUST resolve.
